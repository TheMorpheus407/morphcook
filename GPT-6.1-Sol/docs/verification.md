  positive attributes, time/calorie boundaries, calorie-only override, ranking
  order, temporal bonuses, staleness, and corpus-wide diet invariants.
- Mass and compatible volume conversion, serving scaling, incompatible units,
  checked state/provenance, variety/frequency/month statistics, ISO weeks and DST.
- Plain JSON and GZip round trips, encryption, password prompts/reasons, fresh
  salt/nonce, authenticated data tampering, compression, malformed collections,
  future profile fields, merge/replace, idempotence, and invalid restore isolation.
- Core-only launch, concurrent partition loading, bilingual text/tag search,
  on-demand extended content, failed-asset retry, exact saved IDs, relaunch,
  profile snapshot recovery, weekly swaps and scaled shopping export, wishes,
  and immediate loading of restored extended cooking sessions.
- Pagination offsets/cursors, prefetch, refresh generations, failed-page retry,
  concurrent requests, and disposal during pending loads.
- Wall-clock timer deadlines, pause/resume, background completion, completed
  alert restoration/dismissal, step/serving limits, and opt-in tap debounce.
- Five-step German onboarding, navigation, profile language/accessibility changes,
  authored variant selection, saving/scaling/meal assignment, cooking completion,
  contextual FAQ search, actual long-press drag swaps, shopping checks/clearing,
  and 500 journal records within one week, including archived recipe IDs.
- Home, dish detail, settings, help, profile, backup, insights, history, and
  cooking render at 360, 420, and 900 pixels without layout exceptions. A small
  phone at 1.8× text scale remains usable, including scrolled recipe card grids

## Platform review

The APK is a release-mode review artifact signed with a development key. No
physical-device smoke test, OS share-sheet/file-provider interaction, iOS native
build, public-store signing, or human culinary review is represented by the
automated results above. The shared Flutter UI and backup logic are tested;
native plugins compile in the Android release build. Test the OS file flows and
background/relaunch behavior on target devices before store publication.

## Reproduce

```sh
./tools/flutter.sh analyze --no-pub
./tools/flutter.sh test --no-pub --reporter expanded
python3 -B tools/validate_corpus.py
python3 -B -m unittest discover -s pipeline -p 'test_*.py' -v
./tools/flutter.sh build apk --release --no-pub
```
